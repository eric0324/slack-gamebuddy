## Context

動機見 proposal.md。規則細節見 `specs/deception/*`。

### 原版規則查證 (Deception: Murder in Hong Kong，Jolly Thinkers／Grey Fox Games)

查了 RulesPal 收錄的規則書全文、gamerules.com 的規則摘要和幾篇玩家評論：

- **人數** 4～12；一局約 20 分鐘。
- **角色**：4～5 人是 1 鑑識官 (Forensic Scientist) ＋1 兇手 (Murderer) ＋其餘調查員 (Investigator)；6～12 人可以選用共犯 (Accomplice) 和目擊者 (Witness)，而且**有目擊者時一定要有共犯**。鑑識官開局公開身分。
  - 共犯：知道兇手是誰和答案，和兇手同一陣營。
  - 目擊者：屬於調查員陣營，知道兇手和共犯是哪兩位，但不知道誰是誰，也不知道答案。
- **發卡**：鑑識官以外每人 4 張線索卡 (Clue) ＋4 張手段卡 (Means)，公開放在面前 (規則書提到 3 張較簡單、5 張較難)。鑑識官不拿卡、改用提示板 (Scene tiles)。鑑識官以外每人 1 枚徽章 (Badge)。
- **夜晚 (The Crime)**：大家閉眼，兇手指出自己面前 1 張線索 (Key Evidence) 和 1 張手段 (Means of Murder)，共犯同時睜眼得知；有目擊者時，鑑識官再向目擊者指出兇手和共犯 (不分誰是誰)。
- **提示板**：1 張死因板 (Cause of Death，紫色)、地點板 (Location of Crime，綠色，鑑識官挑最符合的 1 張)、場景板 (棕色)。每張板 6 個選項，每張板最多 1 顆子彈。第 1 輪：死因板＋選定的地點板＋抽 4 張場景板，共 6 張，6 顆子彈一顆一顆放，放的順序和時機本身也可以是暗示；放子彈時大家可以自由交談。
- **3 輪**：每輪「蒐證 (Evidence Collection)→發言 (Presentation)」。發言從鑑識官左手邊開始順時針，每人約 30 秒，發言時其他人不能插話 (除了要破案)。第 2、3 輪鑑識官抽 1 張新場景板換掉 1 張舊板 (**不能換死因板和地點板**)，子彈移到新板上。
- **破案**：鑑識官以外每人整局一次，任何時候都可以喊「我要破案」，指出**另一位玩家**面前的 1 張線索和 1 張手段 (等於同時指認嫌犯)；全對 → 遊戲立刻結束，調查員、鑑識官、目擊者獲勝；錯了鑑識官只說「不對」，交出徽章，之後仍可發言但不能再破案。第 3 輪最後一人發言前沒用的機會作廢。
- **勝負**：有人破案成功 → 好人陣營勝；所有人都失去破案機會 → 兇手 (和共犯) 勝。
- **翻盤 (有目擊者時)**：破案成功後，兇手和共犯商量，指認一位玩家「在審判前被滅口」；指到目擊者 → 兇手和共犯勝，否則好人勝。
- **鑑識官的黃金守則**：只能用子彈和回答破案的「對／不對」溝通。
- 另有事件板 (Event tiles) 變體，第 2 輪後混入場景板疊；本 change 不做。

### 程式架構

- 房間邏輯、`runGame`、`shuffle`、`reply`、`startTimer`、`lobbyEvent`、`cancelGame` 都在 `src/common.ts`。不支援 bot 的做法照猜猜看 (`src/wager.ts`)：`addBot`／`removeBot` action 直接回「詭影神探不支援 bot」；GameDef 加 `noBots: true`。
- 私下身分用 `dm` 事件 (照阿瓦隆)；夜晚兇手選答案、翻盤指認目擊者用 `audience: 'user'` 的 prompt (私訊附按鈕，按鈕 value 帶頻道，按下後回到這個頻道的遊戲)。
- 回合面板和私人選單照富饒之城／矮人礦坑：頻道 prompt 帶 `ref` 原地更新；面板上的按鈕開 `audience: 'ephemeral'` 的私人選單，選單上的按鈕用 `replace: true` 原地換內容。
- `src/slack.ts` 每個頻道只記**最後一個**帶 `ref` 的頻道 prompt (`promptTs`)；不帶 `ref` 的頻道 prompt 和 `announce` 不會蓋掉它。所以發言短訊息 (不帶 `ref`) 不影響面板原地更新。
- `src/slack.ts` 的 prompt 只有按鈕 (沒有 select)，`perRow` 控制每列幾顆；Slack 每個 actions block 最多 25 顆按鈕、一則訊息最多 50 個 block、section 文字最多 3000 字。
- 討論是頻道一般訊息，但 engine 不需要讀，所以 GameDef **不加 `chat`**。
- 不需要新的 GameEvent 種類、不需要 modal、不需要改 `src/slack.ts`。

## Goals / Non-Goals

**Goals:**
- 所有遊戲操作都用按鈕，不用打字指令 (討論本來就是打字)
- 鑑識官以外的人從頻道訊息就能看到所有公開資訊 (提示板、子彈、每人的卡、誰還有徽章)
- 任何一個人掛機，遊戲都會往前走；鑑識官整個掛機時不讓大家白玩

**Non-Goals:**
- 不做事件板變體、不做 3 張／5 張卡的難度選項、不讓房主選要不要共犯和目擊者
- 不支援 bot
- 不做發言時的禁言 (Slack 擋不住，也沒必要)
- 不做自訂秒數

## Decisions

1. **檔案拆分**：`src/deception.ts` (engine，state／action／事件) ＋ `src/deceptionCards.ts` (手段詞庫、線索詞庫、死因板、地點板、場景板，純資料)。詞庫和提示板內容很長，和流程分開比較好讀；和 `tabooCards.ts`、`saboteurCards.ts` 的拆法相同。

2. **共犯和目擊者 6 人以上一律加入** (原版是選用)。理由：Slack 沒有「開局前選規則」的介面，加一個開房參數只為這件事不值得；人多時加入共犯和目擊者讓兇手陣營不會太弱。4～5 人照原版不加。→ **需要使用者確認**。

3. **鑑識官隨機選** (使用者已決定)，開局公開。

4. **發言輪流、討論自由**：原版發言時不能插話，但 Slack 擋不住打字，所以「輪流」只是提示和計時：每輪依座位從鑑識官下一位開始，輪到的人有 90 秒 (原版 30 秒，打字比說話慢，放寬到 90 秒)，按「✅ 說完了」或逾時就換下一位。系統不讀頻道訊息。發言短訊息只有一行加兩顆按鈕，不帶 `ref`。
   - 替代方案「完全自由討論＋每輪固定 3 分鐘」：較簡單，但人多時容易有人整局沒講話，也少了「輪到我要表態」的壓力，不採用。

5. **破案由系統判定、公開猜測內容**：原版是鑑識官說「不對」，這裡 engine 知道答案，直接判定 (避免鑑識官掛機卡住，也避免手誤)。猜測內容公開在頻道 (原版是當眾指出)，錯了只說「不對」。

6. **破案流程三步、最後一步直接送出**：選嫌犯 (最多 11 顆)→ 選手段 (4 顆＋返回)→ 選線索 (4 顆＋返回，按下就送出)。沒有另外的「確認」步驟：返回鍵已經能修正前兩步，多一步確認會讓人在發言時間內來不及。按鈕 value 帶完整的猜測，所以選單本身不需要記在 state 裡 (stateless)，只有最後送出才改 state。

7. **鑑識官放子彈兩步**：先選板、再選選項；選「案發地點」時一次列 4 張地點板 (4 列 × 6 顆 = 24 顆，每列一個 actions block)，按一顆就同時決定地點板和子彈。第 2、3 輪：先選要換掉的舊場景板 (4 顆)，再選新板的選項 (6 顆)。子彈放下就不能移，符合原版「一顆一顆放」，也讓放的順序成為暗示。

8. **鑑識官掛機的防禦**：系統**不替鑑識官隨機放子彈** (隨機子彈是錯誤暗示，比沒有暗示更糟)。第 1 輪逾時：放了幾顆算幾顆，沒放的板沒有子彈；**一顆都沒放就中止遊戲** (公告答案、不送 `result`、沒有再來一局)，因為沒有任何提示時這局沒有意義。第 2、3 輪逾時就不換板。→ **需要使用者確認**「一顆都沒放就中止」。

9. **翻盤只由兇手按**：原版是兇手和共犯商量。這裡只私訊兇手按鈕，另外私訊共犯「兇手正在指認目擊者」，兩人想商量可以自己用 Slack 私訊 (共犯本來就知道兇手是誰)。逾時 120 秒視為沒指到 → 好人勝。→ **需要使用者確認**。

10. **提前結束**：破案失敗後，若調查員和目擊者的徽章都用光，立刻判兇手陣營勝 (剩下有徽章的只有兇手和共犯，他們不會去破自己的案)。這會讓大家知道「剩下有徽章的是壞人」，但遊戲同時結束、身分全公開，沒有影響。

11. **計時** (都用 `startTimer` 的單一 phase 計時器)：
    | 階段 | 秒數 | 逾時 |
    |---|---|---|
    | 夜晚 | 90 | 兇手沒選的項目隨機選 (不公告逾時) |
    | 第 1 輪蒐證 | 240 | 沒放的板沒子彈；0 顆就中止 |
    | 第 2、3 輪蒐證 | 120 | 不換板 |
    | 每人發言 | 90 | 換下一位 |
    | 翻盤 | 120 | 視為沒指到目擊者，好人勝 |

12. **按鈕 value** (kind `deception`)：
    | 用途 | value | 說明 |
    |---|---|---|
    | 面板 | `fs:<pseq>`、`solve`、`me` | 開鑑識官選單／開破案選單／看身分 |
    | 發言短訊息 | `done:<tseq>`、`solve` | 說完了／破案 |
    | 夜晚 (私訊) | `nm:<i>`、`nc:<i>` | 兇手選第 i 張手段／線索 |
    | 鑑識官第 1 輪 | `fb:<pseq>:<slot>`、`fp:<pseq>:<slot>:<opt>`、`fl:<pseq>:<board>:<opt>`、`fback:<pseq>` | slot 是 `cause`／`s0`～`s3`；fl 是地點板 |
    | 鑑識官第 2、3 輪 | `fs:<pseq>`、`fx:<pseq>:<slot>`、`fn:<pseq>:<slot>:<opt>` | 選換掉的板／在新板放子彈 |
    | 破案 | `sus:<target>`、`sm:<target>:<mi>`、`sc:<target>:<mi>:<ci>`、`sback:<target?>` | sc 送出 |
    | 翻盤 (私訊) | `wit:<target>` | |

    `pseq` 每進入新的蒐證／發言階段 +1，面板 `ref: deception:panel:<pseq>`；`tseq` 每換一位發言者 +1。過期的 `pseq`／`tseq` 一律回「這個階段已經結束了」。破案按鈕不帶 seq，送出時才檢查階段和徽章。

13. **State (草稿，`src/deception.ts`)**：
    ```ts
    type Role = 'scientist' | 'murderer' | 'accomplice' | 'witness' | 'investigator';
    interface DPlayer { id: string; role?: Role; means: string[]; clues: string[]; badge: boolean }
    interface Board { title: string; options: string[] }   // 6 個選項
    interface Placed { board: Board; bullet?: number }
    interface DState {
      game: 'deception'; channel: string; host: string;
      phase: 'lobby' | 'night' | 'evidence' | 'present' | 'reversal' | 'ended';
      players: DPlayer[];
      round: number;                 // 1～3
      answer?: { means?: string; clue?: string };
      cause: Placed;                 // 死因板
      location?: Placed;             // 選定的地點板 (第 1 輪選之前是 undefined)
      scenes: Placed[];              // 4 張場景板
      sceneDeck: Board[];
      fresh?: Board;                 // 第 2、3 輪新抽、還沒放的板
      speakers: string[]; speaker: number;
      pseq: number; tseq: number;
      guesses: { by: string; suspect: string; means: string; clue: string; ok: boolean }[];
      winner?: 'good' | 'evil'; finished?: boolean;
      timerSeq: number; timers: { phase?: number };
    }
    ```

14. **Action**：`new`、`join`、`leave`、`start`、`cancel`、`addBot`、`removeBot`、`rematch`、`me`、`nightMeans`、`nightClue`、`fsMenu`、`fsBoard`、`fsPlace`、`fsLocation`、`fsBack`、`fsSwap`、`fsNew`、`done`、`solveMenu`、`suspect`、`solveMeans`、`solveBack`、`solve`、`witness`、`timeout`。

15. **頻道訊息格式**：純文字，提示板一行一張、子彈用【】：
    ```
    第 1/3 輪．蒐證 (鑑識官：@C)
    死因：窒息／鈍器重擊／失血過多／【中毒】／急病發作／意外事故
    案發地點：(還沒選)
    兇手個性：冷靜／衝動／狡猾／膽小／自大／細心
    ...
    場上一覽
    @A　手段：菜刀、繩子、毒藥、雨傘　線索：鑰匙、手錶、日記、口紅
    ...
    還有徽章：@A @B @D @E
    ```
    emoji 只用在按鈕 (🧪 🔍 🗂️ ✅ ↩️) 和角色名稱 (🔬 鑑識官等)，卡牌和提示板文字不配 emoji。

16. **詞庫與提示板**：內容在下一節，由 `src/deceptionCards.ts` 匯出 `MEANS`、`CLUES`、`CAUSE_BOARD`、`LOCATION_BOARDS`、`SCENE_BOARDS`。發卡時兩個詞庫各自洗牌後依序發，保證同局不重複 (12 人局最多用 44 張，遠少於 100)。詞庫只放常見、好懂、不超過 6 個字的詞；避免過度血腥的描述。

## Risks / Trade-offs

- [面板太長、超過 Slack section 3000 字] → 12 人局估算：場上一覽 11 行 × 約 70 字 + 提示板 6 行 × 約 50 字，約 1100 字，遠低於上限；測試加一條 12 人局面板長度 < 3000 的檢查
- [討論訊息把面板推上去] → 每輪蒐證和發言各發一則新面板 (一局 6 則)，發言短訊息也有「🔍 破案」，不用往上捲找面板
- [鑑識官在頻道打字洩題] → 系統擋不住；身分私訊寫清楚規則，靠玩家自律 (和原版一樣)
- [一位玩家同時在破案選單裡，階段剛好換了] → 破案按鈕不帶 seq，送出時只檢查「現在能不能破案」和徽章，階段換了不影響；遊戲已結束時舊按鈕被忽略
- [6 人以上一律有共犯和目擊者，和原版「選用」不同] → 寫在規則 wiki；之後真的需要再加開房參數
- [發言 90 秒乘上 11 人 × 3 輪，最長約 50 分鐘] → 說完就按「✅ 說完了」，正常一輪遠短於上限；wiki 提醒
- [詞庫有些詞偏重口味] → 已避開血腥描述；使用者看過詞庫後可以直接改 `deceptionCards.ts`，只影響資料
