## Context

架構照 2026-10-15 重構後的做法：`src/meme.ts` 純邏輯 `applyMeme(state, action, rng)`，房間邏輯用 `src/common.ts` 的 `joinRoom`、`addBots`、`runGame` 等；`src/games/meme.ts` 匯出 `GameDef`（help、parse、button、modals）。手牌選單、視窗、`ref` 更新同一則訊息，都是現有遊戲（壽司派對、變色龍、截碼戰）用過的做法。

## Goals / Non-Goals

**Goals:** 規則一句話講完；想不到梗也能出手牌；bot 能湊人數；梗圖每局不重複。

**Non-Goals:** 不把文字疊到圖片上（只在訊息裡顯示圖和文字）；不在執行時呼叫 Imgflip API；不做裁判模式；不做換手牌。

## Decisions

- **梗圖清單是寫死的檔案**：`src/memeImages.ts` 匯出 `MEME_IMAGES: { name: string; url: string; source: 'imgflip' | 'tw' }[]`。Imgflip 的部分現在從 `https://api.imgflip.com/get_memes` 抓一次，只留 `box_count` ≤ 2、配一句話就看得懂的模板（約 40～60 張），名字翻成中文；台灣梗圖先留空陣列和註解，使用者給網址後直接加。這樣 engine 不碰網路，測試穩定。
- **announce 加 `image`**：`{ type: 'announce', text, image?: string }`，adapter 和 GIF 一樣加一個 image block（`alt_text` 用梗圖名稱）。有 `gif` 和 `image` 時兩個都顯示。
- **答案送出後不能改**：避免「出手牌後改成自己寫」要把牌還回手上的複雜度。
- **投票可以改**：投票是單一按鈕列，改票只是換值，簡單；投票訊息用 `ref` 顯示「已投 N/M」，不顯示誰投誰。
- **匿名**：投票前只列答案文字和字母，不標 ✍️，避免大家只投自己寫的或猜作者。
- **計分**：每得 1 票 +1。不另外給「本輪最高票」加分，規則比較短。
- **超時自動出牌**：從手牌隨機出一張並補牌，讓投票的選項數量穩定；頻道公告「⌛ @某人 沒送出，系統幫他出了一張」。
- **只有 2 個答案以上才投票**：理論上 3 人以上一定有 3 個答案（超時也自動出牌），不需要特別處理。
- **牌庫用完**：棄牌洗回牌庫再抽。300 句、8 人 6 輪最多用 7×8＋6×8 = 104 張，正常不會用完，但保留這條規則。
- **文字卡長度**：每句 ≤ 30 字（按鈕字數限制 75，留安全距離）；題庫測試檢查不重複、長度、數量 ≥ 300。

## Risks / Trade-offs

- [Imgflip 網址失效] → 那張圖顯示不出來，遊戲照常進行；清單是寫死的，可以手動換。
- [自己寫的內容不當] → 和頻道聊天一樣由使用者自律，不做過濾。
- [Slack 視窗打不開] → 和其他遊戲一樣提示改用 `/game meme write <文字>`。
