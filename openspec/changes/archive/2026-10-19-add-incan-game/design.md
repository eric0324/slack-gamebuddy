## Context

### 原版規則查證（Incan Gold，Eagle-Gryphon／Gryphon Games 英文版；Diamant 是同一款的原名）

查了官方規則書整理（rulespal.com 收錄的英文規則書、Order of Gamers 規則摘要）和 Board Game Arena 的說明頁，確認如下：

- **人數**：3～8 人。
- **探險卡 30 張**：寶藏卡 15 張，寶石數 1、2、3、4、5、5、7、7、9、11、11、13、14、15、17（合計 124）；危險卡 5 種各 3 張（蜘蛛、毒蛇、火焰／噴火、落石、木乃伊）。BGA 說明頁只列 14 張（少了 17），規則書和多數資料都是 15 張，採 15 張。
- **神器 5 張**：開局不在牌庫；每座神殿（共 5 座）開始時加 1 張再洗牌。**沒翻到的神器留在牌庫**，之後的神殿可能翻到。
- **一步**：翻 1 張牌。寶藏 → 洞裡的人平分（無條件捨去），餘數留在卡上；神器 → 放在路上；危險 → 第一張沒事，同種第二張出現時探險失敗。
- **選擇**：沒失敗時，洞裡的人同時暗中決定繼續或離開，同時公開。
- **離開**：離開的人平分路上所有卡上剩下的寶石（餘數留在路上），連同這次探險拿到的寶石放進帳篷，之後安全；**只有一個人離開**時，他另外拿走路上所有神器；兩人以上同時離開，誰都拿不到神器。
- **探險結束**：所有人都離開，或同種危險出現第二張。失敗時還在洞裡的人歸還這次探險拿到的寶石；**造成失敗的那張危險移出遊戲**（之後那種危險只剩 2 張）。路上沒被拿走的神器也移出遊戲。其他翻開的牌洗回牌庫。
- **神器價值**：「最先離開神殿的 3 個神器各 5 分，第 4、5 個各 10 分」——依被帶回營地的順序算，不是依神器加入的順序。BGA 的寫法也是「第 4、第 5 個神器 10 分」。
- **勝負**：5 座神殿後帳篷裡寶石（1 顆 1 分）加神器分數最高者勝；**同分時神器多者勝**，還是同分規則書寫「那就再玩一次！」。
- **帳篷**：原版帳篷是遮住的，別人看不到你存了多少（但離開時分到幾顆是公開動作，有心人可以自己記）。
- 新版 Diamant（2005 後的 Schmidt/IELLO 版）神器改成 5、7、8、10、12 分、另有「每人起始 1 張神器」等差異；使用者指定照原版，採 Incan Gold 的 5／5／5／10／10。

### 程式架構

- 房間邏輯（`joinRoom`、`leaveRoom`、`addBots`、`removeBots`、`cancelGame`）、`runGame`（`afterChange` 讓 bot 行動）、`shuffle`、`reply`、`startTimer`、`lobbyEvent` 都在 `src/common.ts`；壽司派對、炸彈貓都這樣用，印加寶藏照抄。
- 壽司派對示範了「同時選、同時揭曉」：每一步一則頻道 prompt 帶 `ref: sushigo:<seq>`（同一步用同一個 ref 更新「已選 N/M」），選擇私下確認、揭曉前可以改，按鈕 value 帶 `seq` 擋舊按鈕，逾時的真人用 bot 規則替他選。印加寶藏的選擇只有兩個，直接把兩顆按鈕放在頻道訊息上，不需要另開私下選單。
- `{ type: 'ephemeral', to, text }` 只讓某人看到；`{ type: 'result', players, winners }` 送戰績。
- 不需要新的 GameEvent 種類、不需要 modal、不需要改 `src/slack.ts`。

## Goals / Non-Goals

**Goals:**
- 只用兩顆按鈕就能玩完；選擇在揭曉前不公開
- 規則照原版（牌庫、分寶、神器、危險移除、同分看神器）
- 有人掛機也一定會推進；1 位真人 + bot 可以玩完整局
- 一局約 10～15 分鐘

**Non-Goals:**
- 不做新版 Diamant 的神器分數和規則差異
- 不做遊戲中的打字指令（選擇只用按鈕）
- 不做自訂神殿數或秒數
- 不做「回營地時把餘數放在自己選的卡上」（見 Decision 3，結果相同）

## Decisions

1. **牌的代號與顯示**：
   | 種類 | 代號 | 顯示 | 張數 |
   |---|---|---|---|
   | 寶藏 | `gem:<n>` | 💎 n 顆寶石 | 15（1、2、3、4、5、5、7、7、9、11、11、13、14、15、17） |
   | 危險 | `spider`／`snake`／`fire`／`rock`／`mummy` | 🕷️ 蜘蛛／🐍 毒蛇／🔥 火焰／🪨 落石／🧟 木乃伊 | 各 3 |
   | 神器 | `relic` | 🏺 神器 | 每座神殿加 1，共 5 |
2. **神殿流程**：
   - 開始：牌庫 = 上一座神殿結束後留下的牌（寶藏全部、還沒移除的危險、還沒翻到的神器）＋ 1 張新神器，洗牌；所有人回到洞裡、這座神殿的寶石歸零、路上清空。
   - 每一步：`seq++`，翻 `deck[0]`。寶藏 → `floor(n / 洞裡人數)` 給每個洞裡的人，餘數加到 `path`；神器 → `pathRelics++`；危險 → 這種已經出現過就失敗，否則記錄出現過。
   - 沒失敗 → 頻道步驟訊息 + 開始 30 秒計時，等洞裡的人選擇。
   - 揭曉：回營的人平分 `path`（`floor(path / 回營人數)`，餘數留在 `path`），連同自己這座神殿拿到的寶石加進帳篷；恰好 1 人回營時，他拿走 `pathRelics` 張神器，每張的分數依全局第幾個被帶回營地決定（`relicsTaken` 從 0 開始，第 1～3 個 5 分，第 4、5 個 10 分）。洞裡沒人了 → 神殿結束；否則下一步。
   - 失敗：洞裡的人這座神殿的寶石歸零；造成失敗的那張危險移出這局（同種的另一張洗回）；神殿結束。
   - 神殿結束：路上的神器（`pathRelics`）移出這局；第 5 座結束 → 遊戲結束，否則下一座。
   - 防禦：牌庫翻完還沒結束時（照原版牌數不會發生：最多移除 4 張危險，第 5 座仍至少有一種危險剩 3 張），洞裡的人視為全部回營地。
3. **路上寶石只記總數**：原版「回營的人平分路上所有卡上的寶石，餘數放在一張卡上」，之後再回營的人一樣拿整條路的寶石，所以記一個 `path` 總數就和原版結果相同，不必記每張卡。
4. **同時選擇的介面**：每一步一則頻道 prompt `{ kind: 'incan', audience: 'channel', ref: 'incan:<seq>' }`，內容：
   - 第 N/5 座神殿第 K 步、剛翻到的牌、路上的牌（依順序）、路上剩餘寶石和神器數、已出現的危險、牌庫剩幾張
   - 洞裡的人（各自這座神殿已拿到的寶石，原版這是公開的）、已在營地的人
   - 「已選 N/M，還沒選：…」
   - 按鈕 `go:<seq>`「🔦 繼續探險」、`camp:<seq>`「⛺ 回營地」

   按鈕的人私下看到「你選了 🔦 繼續探險（揭曉前可以改）」；不在遊戲、已在營地、`seq` 過期都只讓本人看到提示。同一步的 `ref` 更新「已選」人數；揭曉時把這則訊息改成「揭曉：繼續 …／回營 …」並拿掉按鈕（`options: []`），另外公告回營分寶和神器的結果，再發下一步的新訊息。
5. **逾時**：選擇計時 `CHOOSE_MS = 30_000`。時間到還沒選的**真人一律視為回營地**（使用者決定：比 bot 代選好預期；掛機的人也不會一直留在洞裡爆掉），揭曉公告標示「（逾時，自動回營）」。舊的計時器（`timerSeq` 不符）忽略。
6. **bot 決策**（細節見 `incan/bots`）：每一步開始時 bot 立刻做出選擇（算在「已選」裡），不需要 rng，方便測試。危險率 `risk` = 牌庫中「這座神殿已出現過的危險種類」剩下的張數 ÷ 牌庫張數。依序：
   1. 洞裡只剩自己而且路上有神器 → 回營地（一定拿到神器）
   2. `risk ≥ 0.2` → 回營地
   3. 這座神殿已拿到 ≥ 10 顆寶石而且 `risk > 0` → 回營地
   4. 其他 → 繼續探險
7. **帳篷保密**：頻道不顯示帳篷總數；每座神殿結束時，每位真人私下收到「你的帳篷：X 顆寶石、神器 Y 個（Z 分）」。遊戲結束才公告每個人的寶石、神器和總分。回營當下「誰回營、每人分到幾顆、誰拿到神器」照原版公開。
8. **勝負**：總分 = 帳篷寶石 + 神器分數。最高分者勝；同分比神器張數，多的勝；還是同分就並列（原版「再玩一次」不適合 bot 自動化，改成並列，列為待確認）。
9. **State（草稿，`src/incan.ts`）**：
   ```ts
   type Hazard = 'spider' | 'snake' | 'fire' | 'rock' | 'mummy';
   type Card = { gem: number } | { hazard: Hazard } | { relic: true };
   interface IPlayer {
     id: string;
     tent: number;          // 帳篷裡的寶石
     relics: number[];      // 帶回的神器分數（5 或 10）
     carry: number;         // 這座神殿拿到、還沒帶回的寶石
     inCave: boolean;
     choice?: 'go' | 'camp';
     auto?: boolean;        // 這一步是逾時代選
   }
   interface IState {
     game: 'incan'; channel: string; host: string;
     phase: 'lobby' | 'choose' | 'ended';
     players: IPlayer[];
     temple: number;        // 第幾座神殿（1～5）
     step: number;          // 這座神殿第幾步
     seq: number;           // 全局步數：頻道訊息 ref、擋舊按鈕
     deck: Card[];          // deck[0] 是下一張
     revealed: Card[];      // 這座神殿翻開的牌（顯示用，神殿結束洗回牌庫）
     seen: Hazard[];        // 這座神殿出現過的危險
     path: number;          // 路上剩餘寶石
     pathRelics: number;    // 路上的神器數
     relicsAdded: number;   // 已加入牌庫的神器數（= temple）
     relicsTaken: number;   // 全局已被帶回營地的神器數（決定 5 或 10 分）
     winners?: string[]; timerSeq: number; timers: { phase?: number };
   }
   ```
10. **Action**：`new`、`join`、`leave`、`start`、`cancel`、`addBot`、`removeBot`、`rematch`、`choose { user, seq, choice: 'go' | 'camp' }`、`timeout { id }`。
11. **按鈕 value**（kind `incan`）：`go:<seq>`、`camp:<seq>`；共通的 `join`、`leave`、`start`、`rematch` 照其他遊戲。

## Risks / Trade-offs

- [頻道訊息多：每步一則，一座神殿可能 10 步以上] → 每步只發一則步驟訊息並原地更新，揭曉結果合併在同一則；回營／失敗另發一則短公告
- [30 秒對 8 人局偏長] → 全員選完立刻揭曉，bot 立刻選；常數集中在 `CHOOSE_MS`
- [帳篷保密但回營分寶是公開的，玩家可以自己算] → 和原版相同，接受
- [逾時一律回營可能讓短暫離開的人提早出局] → 公告標示「逾時，自動回營」，規則簡單可預期
