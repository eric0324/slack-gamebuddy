## Context

- 2026-10-15 重構後，新遊戲 = `src/<遊戲>.ts`（純邏輯 engine）+ `src/games/<遊戲>.ts`（`GameDef`）+ `GAMES` 加一行。房間、取消、再來一局、計時、洗牌用 `src/common.ts`（`joinRoom`、`leaveRoom`、`cancelGame`、`runGame`、`shuffle`、`reply`、`startTimer`、`lobbyEvent`）。
- 已有的 adapter 能力，四葉草都用得到、**不用改 adapter**：
  - `modal` 事件的 `fields?: string[]` → 多欄位視窗（`f0`～`f3`），`GameDef.modals` 轉成 action（截碼戰 3 欄）
  - 頻道 `prompt` 帶 `ref`：同一個 `ref` 就 `chat.update` 同一則訊息（誰是牛頭王）
  - `prompt` 的 `perRow` 把按鈕分列（Slack 一個 actions block 最多 25 個按鈕）
  - 合作遊戲正常結束送 `{ type: 'result', players, winners: [], score }`（心電感應（合作））
- 官方 So Clover!：每人一片四葉草（2×2 放 4 張卡），每張卡 4 個詞朝 4 邊；每片葉子連著相鄰兩張卡朝外的兩個詞。作者為 4 片葉子各寫一個字的提示；之後大家拿到 4 張卡 + 1 張干擾卡，一起排回原位（含方向）。第 1 次全對 6 分；否則作者拿走錯的卡，第 2 次後每張對的卡 1 分。

## Goals / Non-Goals

**Goals:**
- 從頭到尾不用打字就能玩（提示用視窗、排卡用按鈕）；指令只是備用
- 排卡時多人同時在頻道，操作不會互相打架、結果可預期
- 盤面用純文字就看得懂「每片葉子目前連著哪兩個詞」

**Non-Goals:**
- 不支援 bot
- 不做官方的變體規則（例如兩張干擾卡、計時沙漏版）
- 不在頻道強制作者閉嘴（Slack 做不到）；只擋作者按按鈕，公告提醒作者不要講話
- 不改動 `src/engine.ts`、`src/slack.ts`、`src/index.ts`

## Decisions

### 1. 多人同時操作怎麼決定：擺放者制 + 「🙋 換我排」接手

| | (A) 共用盤面，誰都能按 | (B) 每人私下排一份，逐格投票 | (C) 擺放者制 + 換我排（**建議**） | (D) 共用盤面 + 過半「同意送出」 |
|---|---|---|---|---|
| 操作衝突 | 兩人同時換卡會互相覆蓋，畫面跳來跳去 | 沒有衝突 | 同時只有一人能動 | 同 (A) |
| 討論感 | 有，但「手」太多 | 沒有，各排各的，失去合作遊戲的精神 | 一人動手、大家在頻道出主意，最像實體桌上「一人拿卡、大家指揮」 | 有 |
| 送出時機 | 任何人一按就送，容易誤送 | 每格多數決可能選出同一張卡兩次、或干擾卡，要再處理衝突 | 擺放者決定 | 要追蹤每人同意、盤面一改就重置，3 人局（2 個猜的人）等於全員同意 |
| 有人掛機 | 不影響 | 不投的人不算 | 任何猜的人按「🙋 換我排」接手；再不行就 4 分鐘到自動送出 | 卡在不同意的人身上，只能等超時 |
| 實作量 | 最少 | 最多（每人一份私人盤面 ephemeral，合併規則複雜） | 少：state 多一個 `placer` | 中 |

選 (C)。擺放者預設是座位順序中作者的下一位，每個人大約擺一次；「換我排」不用投票、不用確認，誰按誰拿到（最後按的人為準），簡單而且解決掛機。

### 2. 旋轉怎麼處理：保留官方 4 方向，但盤面只顯示「朝外的兩個詞」

| | (a) 官方 4 方向（**建議**） | (b) 不旋轉 | (c) 每張卡 2 方向 |
|---|---|---|---|
| 難度 | 和官方一樣；第 1 次全對 6 分有份量 | 變簡單很多：方向固定，只剩「哪張卡放哪格」，第 1 次全對太常見 | 介於中間，但不是官方規則，詞卡要重新定義「哪兩組詞是一對」 |
| 顯示 | 每格只顯示朝外的兩個詞（例：格1〔⬆️海 ⬅️山〕），手上的卡列出 4 個詞（順時針）；不需要畫圖 | 最簡單 | 和 (a) 一樣 |
| 操作 | 多一個「🔄 旋轉」按鈕，最多按 3 次 | 少一個按鈕 | 旋轉只有 2 種狀態 |

選 (a)。Slack 難呈現的是「卡片圖」，但玩家真正需要的只是「每片葉子目前連著哪兩個詞」，這個用文字很好表達；旋轉就是一個按鈕，按了盤面立刻更新同一則訊息。若實際玩起來太難，再改成 (b) 只要把發卡和開盤的隨機方向固定成 0、拿掉旋轉按鈕。

### 3. 資料模型（`src/soclover.ts`）

- 卡片：`string[4]`，方向 0 時依序朝 上、右、下、左。方向 `r`（0～3，每 +1 順時針 90 度）時，朝第 `d` 邊（0 上、1 右、2 下、3 左）的詞是 `card[(d - r + 4) % 4]`。
- 格子 0～3（↖ 格1、↗ 格2、↙ 格3、↘ 格4）朝外的邊：格1 [上, 左]、格2 [上, 右]、格3 [下, 左]、格4 [下, 右]。
- 葉子：上 = 格1 上 + 格2 上；右 = 格2 右 + 格4 右；下 = 格3 下 + 格4 下；左 = 格1 左 + 格3 左。
- 「對」= 同一張卡、同一格、同一方向。因為同一局所有詞都不重複，方向不同時朝外的詞一定不同，不會有「看起來一樣但算錯」的情況。
- State（重點欄位）：
  ```ts
  interface SCState {
    game: 'soclover'; channel; host; phase: 'lobby' | 'clue' | 'place' | 'ended';
    players: string[];              // 座位順序（開局洗牌後）
    clovers: Record<string, {       // 每位玩家的四葉草
      cards: string[][];            // 4 張卡，cards[i] 放在格 i
      rot: number[];                // 每格的方向
      decoy: string[];              // 干擾卡
      clues?: string[];             // 上、右、下、左葉的提示；沒送出 = 跳過
    }>;
    queue: string[];                // 要排的作者順序（有送出提示的，隨機）
    cur: number;                    // 正在排 queue[cur]
    board?: {
      hand: { card: string[]; rot: number }[];  // 卡A～卡E（label 固定，不因移動而改）
      slots: (number | null)[];     // 每格放哪張（hand 的 index）
      rot: number[];                // 每張卡（hand index）目前方向
      locked: boolean[];            // 每格是否鎖住
      sel: number;                  // 目前選的格
      attempt: 1 | 2;
      placer: string;
    };
    seq: number;                    // 盤面版本：每開一個新盤面（新片或第 2 次）+1，按鈕 value 帶它
    score: number; finished?: boolean; timerSeq: number; timers: { phase?: number };
  }
  ```
  實作時可依測試再簡化，上面只是方向。

### 4. 盤面訊息與按鈕

- 用 `prompt`（`kind: 'soclover'`、`audience: 'channel'`、`ref: 'soclover:<seq>'`、`perRow: 5`）。每次操作重送同一個 `ref` 的 prompt → adapter 更新同一則訊息；第 2 次或下一片換新的 `seq` → 發一則新訊息。
- 13 個按鈕分 3 列（`perRow: 5`）：
  1. `格1` `格2` `格3` `格4` `🔄 旋轉`（選中的格 label 加 ▶，例如「▶格2」；鎖住的格加 🔒）
  2. `卡A` … `卡E`
  3. `↩️ 拿回` `✅ 送出` `🙋 換我排`
- value 格式：`<seq>:slot:<0-3>`、`<seq>:card:<0-4>`、`<seq>:rotate`、`<seq>:back`、`<seq>:submit`、`<seq>:take`；寫提示按鈕 `clue`。`seq` 不符 → 「這個盤面已經結束了」。
- 盤面文字範例：
  ```
  🍀 第 2／4 片：@A 的四葉草（第 1 次）・擺放者 @B
  ⬆️ 上葉「夏天」：海 ＋ ？
  ➡️ 右葉「速度」：？ ＋ 火
  ⬇️ 下葉「童年」：鐘 ＋ 船
  ⬅️ 左葉「冰冷」：山 ＋ 雪
  ↖ 格1：卡C〔⬆️海 ⬅️山〕　↗ 格2：（空）
  ↙ 格3：卡A〔⬇️鐘 ⬅️雪〕　↘ 格4：卡E〔⬇️船 ➡️火〕
  ✋ 手上：卡B 貓→雲→鑰匙→蛇　卡D 星星→傘→蛋糕→鏡子
  ```
  （手上的卡從目前朝上的詞開始順時針列出。）

### 5. 寫提示的私訊和視窗

- 私訊範例（作者自己的四葉草）：
  ```
  🍀 你的四葉草（只有你看得到）
  　　　　⬆️ 上葉：海 ＋ 船
  ⬅️ 左葉：山 ＋ 雪　　➡️ 右葉：火 ＋ 鐘
  　　　　⬇️ 下葉：貓 ＋ 雲
  ↖ 格1〔⬆️海 ⬅️山〕　↗ 格2〔⬆️船 ➡️火〕
  ↙ 格3〔⬇️貓 ⬅️雪〕　↘ 格4〔⬇️雲 ➡️鐘〕
  回到頻道按「✍️ 寫提示」，每片葉子寫一個提示（不能用卡上的詞）。
  ```
  不用 code block 畫框線：中文字寬在各平台不一致，框線容易歪。
- `openClue` → `{ type: 'modal', kind: 'socloverClue', title: '寫提示', label: '', fields: ['⬆️ 上葉：海 ＋ 船', '➡️ 右葉：…', '⬇️ 下葉：…', '⬅️ 左葉：…'] }`。視窗只有本人看得到，標籤帶詞對沒有洩漏問題。`GameDef.modals.socloverClue` 轉成 `{ type: 'clue', user, texts }`。
- 指令備用：`/game soclover clue a / b / c / d`，用 `/` 切成剛好 4 個並去掉前後空白（同截碼戰）。
- 提示 1～15 字；不能和自己 4 張卡上任何一個詞完全相同（只比完全相同，不比「包含」，避免單字詞誤擋）。送出後不能改（簡單，也避免排卡開始後改提示）。

### 6. 時間限制與超時

| 階段 | 時間 | 提早結束 | 超時 |
|---|---|---|---|
| 寫提示 | 5 分鐘（要寫 4 個） | 全部送出 | 沒送出的四葉草跳過、0 分；全部沒送出 → 直接結束，總分 0（照常送 result） |
| 排卡第 1 次 | 4 分鐘 | 擺放者送出 | 以目前盤面送出，空格算錯；沒全對照常進第 2 次 |
| 排卡第 2 次 | 4 分鐘 | 擺放者送出 | 以目前盤面送出，空格算錯 |

一局最長約 5 + 8 × 6 = 53 分鐘；實際上擺放者會提早送出，房主也隨時可以取消。

### 7. 計分、評價、戰績

- 每片：第 1 次全對 6 分；否則第 2 次結束時盤面上對的張數（含鎖住的）。官方原文是第 2 次後「每張放對的卡 1 分」，鎖住的卡也在盤面上，所以一起算。
- 滿分 = 6 × 玩家數（被跳過的四葉草也算，避免「不寫提示反而評價變高」）。
- 評價依比例（整數比較 `score * 100 >= pct * max`）：100、85、70、50、30、0。
- 戰績 `result.score` = 全隊總分（原始分數，和公告一樣）。缺點是 6 人局的上限（36）比 3 人局（18）高，`/game rank soclover` 依最高分排行時人多的局佔優勢；另一個做法是記百分比（0～100）。先選原始分數，和花火、心電感應（合作）一致，列為待決定問題。

### 8. 詞庫：新增 `src/socloverWords.ts`，不直接 import 截碼戰詞庫

- 需要量：6 人 × 5 張 × 4 詞 = 120 詞，詞庫至少 200 才有變化。
- 截碼戰詞庫（`src/decryptoWords.ts`）只有 160 個，而且有一整組抽象詞（夢、時間、運氣…），不符合「具體名詞」。直接 import 再 filter 會讓兩款遊戲的詞庫綁在一起，改截碼戰詞庫時會影響四葉草。
- 做法：新檔 `SOCLOVER_WORDS`，複製截碼戰詞庫裡的具體名詞（約 140 個）再擴充到 240 個左右（文具、運動、樂器、家電、衣物、建築等），附測試檢查數量、不空白、不含空白字元、不重複。

### 9. 其他

- 座位順序：開局 `shuffle(players)`，公告出來；擺放者 = 作者在座位順序的下一位。
- 排卡順序：有送出提示的作者 `shuffle` 後依序。
- 取消：`cancelGame(c, user, extra)`，正在排卡時 `extra` 是這片的正確擺法。
- `GameDef`：`kind: 'soclover'`、`emoji: '🍀'`、`name: '四葉草'`、`players: '3～6 人'`、`category: 'coop'`、`desc: '全員合作，為自己的四葉草寫提示，大家一起把詞卡排回原位'`、`noBots: true`。`GAMES` 加在最後（變色龍後面），所以大廳「🤝 合作」分類依序是一字千金、花火、心電感應（合作）、四葉草。

## Risks / Trade-offs

- [擺放者一人操作，其他人只能打字討論] → 實體遊戲也常是一人動手；「🙋 換我排」讓任何人隨時接手，不需要等待或投票
- [多人同時按「換我排」] → 每個 action 依序處理，最後按的人是擺放者，盤面會顯示目前是誰，不會不一致
- [盤面每次操作都 `chat.update`，Slack 有 rate limit（約每秒 1 次）] → 一個人連續按的速度通常不會超過；真的被限流時 adapter 會丟錯誤 log，下一次操作會再更新成最新狀態
- [4 方向旋轉對新手偏難] → 盤面直接顯示每片葉子目前的詞對，旋轉後立刻看到效果；太難時改成不旋轉的成本很低（見決策 2）
- [作者在頻道洩漏答案] → Slack 無法阻止，開始排卡時公告提醒作者保持安靜
- [一局可能很長] → 每階段都可提早結束，房主隨時可取消
