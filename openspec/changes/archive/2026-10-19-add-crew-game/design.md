## Context

- **原版機制 (The Crew: The Quest for Planet Nine，查證自官方規則書整理)**：
  - 40 張大牌：粉、藍、綠、黃 4 色各 1～9 (36 張)，加上火箭 1～4 (4 張)。全部發完：3 人時有一人多 1 張 (13／13／14)，最後一墩打完後那張剩下的牌不打；4 人每人 10 張；5 人每人 8 張。
  - 持有火箭 4 的人宣告自己是指揮官，先挑任務、先領第一墩；之後每墩由贏的人領下一墩。
  - 吃墩：必須跟出領出的顏色；沒有這個顏色時可以出任何牌 (包含火箭)。有火箭時最大的火箭贏，否則領出顏色最大的贏。火箭領出時，其他人有火箭就要跟火箭。
  - 任務牌：另一副 36 張小牌 (對應每張彩色牌)。每關翻開規定數量的任務牌，從指揮官開始輪流各挑一張，直到挑完 (每人任務數可以不同)。擁有任務的人要親自吃下包含那張牌的墩；被別人吃走就立刻失敗。全部任務完成即成功。
  - 順序標記：1～5 是「所有任務中」第幾個完成；Ω 是最後一個完成；> 要在 >> 之前、>> 在 >>> 之前、>>> 在 >>>> 之前 (只限箭頭之間)。同一墩一起完成的連續標記都算數 (不看出牌先後)。違反順序立刻失敗。
  - 通訊：任務分完後才能通訊；只能在墩與墩之間 (含第一墩之前)，不能在一墩進行中。每人每關一次。拿一張彩色牌 (不能是火箭) 公開放在面前，用通訊標記標示位置：上＝我這色最大、中＝我這色唯一、下＝我這色最小；不符合三種之一的牌不能通訊。之後即使不再正確，標記也不動。那張牌還是手牌，之後照常打出。
  - 通訊干擾 (dead zone)：標記不放在牌上，只放在旁邊，別人不知道是哪個位置，但那張牌仍然必須符合三者之一。通訊延遲 (disruption)：第 N 墩之前不能通訊。
  - 指揮官的決定：任務蓋著，其他人看手牌後只回答「可以／不行」包辦全部任務，指揮官選一人 (不能是自己) 包辦全部任務。指揮官分配：任務一張一張翻開，指揮官問大家要不要 (只能回答要／不要)，再指定給某人 (可以是自己)；分配必須平均，任何人不能比別人多 2 張以上。
  - 求救訊號：大家同意時，每人傳一張非火箭牌給鄰居 (會增加嘗試次數紀錄)。
  - 5 人局：從原版第 25 關起的任務關，第一墩之前可以有一人把一張任務交給另一人 (大家討論但不能透露手牌)。
  - 原版不能討論手牌，只能透過出牌和通訊溝通。
- **版權**：原版 50 關的關卡文字、劇情、名稱和逐關設定都有版權。本 change 只沿用上述通用機制，**40 關的名稱、劇情、任務數、標記和特殊規則組合全部自編** (見下方關卡表)，不照抄原版任何一關。顏色改成藍、綠、黃、紫 (不用原版的粉色，順便避開用色太像)。
- 架構照 2026-10-15 重構後的做法：engine 純函式 `applyCrew(state, action, rng)`，房間用 `runGame` 等共用 helper；`src/games/crew.ts` 匯出 `GameDef` (help、parse、button)。私下手牌按鈕照誰是牛頭王的 `handMenu` (`audience: 'ephemeral'`、`perRow`)，牌桌用 `ref` 更新同一則頻道訊息 (壽司派對)。
- **持久化**照 `src/memeStore.ts`：`better-sqlite3`，和戰績同一個檔案 (`statsFile`)，`CREATE TABLE IF NOT EXISTS`，每個頻道一列。adapter 在 `dispatchGame` 把 store 的資料帶進 action (照梗圖大亂鬥開局帶入 `custom` 的做法)，engine 不直接碰檔案。
- 合作遊戲戰績照花火：`result` 帶 `score`、`winners: []`，`StatsStore.recordMatch` 記 `won = NULL`，`best = MAX(score)`。

## Goals / Non-Goals

**Goals:** 規則和原版一致、一關 5～15 分鐘；頻道有長期目標 (打到第 40 關)；失敗馬上知道原因；手牌、出牌、通訊全程按鈕完成。

**Non-Goals:** 不支援 bot；不做求救訊號；不做原版 50 關的劇情與逐關設定；不做「嘗試次數」紀錄與統計 (只記通過的最高關)；不強制禁止聊天；不做 2 人變體和「三人挑戰」變體；不做跨頻道進度；不做自訂秒數。

## Decisions

### 1. 牌與顯示

- 顏色順序：🟦 藍、🟩 綠、🟨 黃、🟪 紫、🚀 火箭。牌寫成「🟦7」「🚀4」。手牌顯示依這個順序再依數字由小到大。
- 3 人時從隨機一人開始依加入順序發，第一位拿到 14 張；13 墩打完後他剩 1 張不打。如果那張是某人的任務牌，任務無法完成 → 第 13 墩結束時判定失敗 (原版也是如此，指揮官和隊員要自己避免)。
- 任務牌從 36 張彩色牌 (不含火箭) 隨機抽，抽出的順序對應關卡表的順序標記：第 1 張配第 1 個標記，依此類推，沒有配到標記的任務沒有順序限制。

### 2. 開局與任務分配 (phase `assign`)

- 發牌後公告：指揮官 (持有火箭 4)、關卡名稱與劇情、規則提醒 (不要在頻道討論手牌)，並附「🃏 手牌」按鈕；每位玩家也收到一則手牌私訊。
- **一般**：頻道公告翻開的任務牌 (含標記)，從指揮官開始依加入順序輪流挑，每次只有輪到的人能按任務按鈕；挑完一輪再一輪，直到挑完。每次挑 60 秒，逾時自動挑剩下的第一張。
- **🎖️ 指揮官指派**：任務一張一張翻開；所有人可以按「🙋 要」「🙅 不要」(公開顯示在同一則訊息)，指揮官按玩家按鈕指定給誰 (可以是自己)。指定後會讓某人比任務最少的人多 2 張時被拒絕。每張 90 秒，逾時自動給目前任務最少的人 (同數從指揮官開始依序)。
- **🎯 單人任務**：任務蓋著 (只公告張數和標記)；指揮官以外的人按「🙋 可以」「🙅 不行」，指揮官按玩家按鈕選一人 (不能是自己)，選完才翻開任務、全部歸他。90 秒逾時：選第一個回答可以的人 (從指揮官下家開始)，都沒有就選指揮官下家。
- **🤒 隊員失能**：分配任務前，指揮官先指定一位隊員 (不能是自己) 整關失能；失能的人不挑任務 (輪流時跳過)，整關贏任何一墩就失敗。90 秒逾時自動指定指揮官下家。
- 分配完公告每個人的任務，進入出牌；指揮官領第一墩。

### 3. 出牌 (phase `trick`)

- 牌桌訊息 (`ref: crew:<seq>:<墩>`，每墩一則、出牌時更新)：第幾墩／共幾墩、輪到誰、這墩已出的牌、每個人的任務 (✅ 完成／⬜ 未完成，含標記)、每個人公開的通訊牌、手牌剩幾張；按鈕「🃏 手牌」「📡 通訊」(5 人局可轉交時再加「🔁 轉交任務」)。
- 「🃏 手牌」只讓按的人看到自己的手牌；輪到他時再列出**合法**的牌按鈕 (`play:<seq>:<牌>`)，不合法的牌不出現。按鈕帶 `seq`，過期的按鈕被拒絕。
- 合法：手上有領出顏色就只能出那個顏色；沒有就可以出任何牌。領出的人可以出任何牌。
- 墩打完：公告這墩的牌、誰贏、完成了哪些任務；接著檢查失敗與成功 (見第 5 點)，都沒有就由贏的人領下一墩。
- 出牌 2 分鐘逾時：自動出合法牌中最小的一張 (彩色牌優先，依數字再依顏色順序；只剩火箭時出最小的火箭)。公告「⏰ 逾時，系統替 X 出了 🟦2」。

### 4. 通訊

- 時機：任務分配完成後，**每一墩的第一張牌打出之前** (通訊窗口)。領出的人也可以先通訊再出牌。窗口外按「📡 通訊」被拒絕並說明要等這墩結束。
- 按「📡 通訊」只讓按的人看到可以通訊的牌：手上每種顏色的最大、最小、唯一那張 (火箭不行)，按鈕標「🟦7 (最大)」「🟩3 (唯一)」「🟨1 (最小)」。同時是最大和最小 (只有一張) 的牌標「唯一」。
- 公告「📡 X 通訊：🟦7 是我藍色最大的」；🔇 通訊干擾時公告「📡 X 通訊：🟦7 (位置不公開)」——系統仍只讓玩家選符合三者之一的牌。
- 每人每關一次，用過就不再列在選單；通訊牌顯示在牌桌直到打出；之後不再正確也不改。
- ⏳ 通訊延遲 N：第 N 墩的窗口開始才能通訊；之前按會被拒絕並說明從第幾墩起。📴 無線電靜默：整關不能通訊，按鈕不出現。

### 5. 任務完成、順序、成功與失敗

一墩打完時，設這墩包含的任務牌集合為 T：
1. T 裡有任何一張的擁有者不是吃下這墩的人 → **失敗** (「🟦7 是 A 的任務，被 B 吃走了」)。
2. 🤒 失能的人吃下這墩 → **失敗**。
3. 其餘 T 都算完成，同一墩的視為同時完成。設這墩之前已完成 k 個、這墩完成 m 個：
   - 數字標記 n：這墩完成的必須滿足 k < n ≤ k+m；還沒完成且 n ≤ k+m 的數字任務 (不在這墩)→ **失敗**。
   - Ω：這墩完成 Ω 時，這墩結束後必須已經全部完成。還有任務沒完成卻完成了 Ω → **失敗**。
   - 箭頭：完成 j 個箭頭的任務時，箭頭比較少的任務必須都已完成或在同一墩完成，否則 **失敗**。
4. 全部任務完成 → **成功** (就算還有手牌也立刻結束)。
5. 手牌都打完 (3 人時是第 13 墩後) 還有任務沒完成 → **失敗**。

失敗公告寫明原因。原版「任務已經不可能完成」不會提前判定，照原版只在違反時判定。

### 6. 5 人局轉交任務

5 人局、第 15 關以後、沒有 🎯 單人任務和 🎖️ 指揮官指派的關卡：第一墩第一張牌打出前，任何擁有任務的人可以按「🔁 轉交任務」選自己一張任務和另一位玩家 (不能給失能的人)，把任務交出去，每關限一次。公告轉交內容。(原版從第 25 關起；本版關卡較少，依比例改為第 15 關起。)

### 8. 頻道戰役進度

- `src/crewStore.ts`：`CrewStore`，表 `crew_progress(channel TEXT PRIMARY KEY, unlocked INTEGER NOT NULL, updated_at INTEGER NOT NULL)`；`get(channel)` 沒有資料時回傳 1；`set(channel, unlocked)`。
- `unlocked` 是「已解鎖的最高關」，1～41 (41 代表 40 關全破)。
- 新房 (`new`)：adapter 把 `unlocked` 帶進 action；預設關卡 = `min(unlocked, 40)`。全破時房間公告「🏆 這個頻道已經全破，可以選任何一關重玩」。
- 成功通過第 L 關：`unlocked = max(unlocked, L+1)` (最多 41)，engine 送出 `crewProgress { unlocked }`，adapter 寫入 store。重打舊關卡成功不會讓進度倒退。
- 再來一局 (rematch)：成功 → 下一關 (`L+1`，已是 40 關則還是 40)；失敗 → 同一關。用上一局 state 的 `unlocked`，不再讀 store。
- 選關：房間階段房主 `/game crew level <n>`，n 必須是 1～`min(unlocked, 40)`；`/game crew level` (不帶數字) 任何人都可以看已解鎖的關卡清單 (編號、名稱、任務數、特殊規則)。
- 重設：房間階段房主 `/game crew reset` → 只讓房主看到確認訊息和「⚠️ 確定重設」按鈕；按下後 `unlocked = 1`、房間關卡改為第 1 關、送 `crewProgress { unlocked: 1 }`，頻道公告進度已重設。
- 沒有設定 store 的 host (測試)：`unlocked` 預設 1，`crewProgress` 被忽略。

### 10. State (草稿)

```ts
type Color = 'blue' | 'green' | 'yellow' | 'purple' | 'rocket';
type Card = `${Color}:${number}`;                       // 例如 'blue:7'
type Token = '1' | '2' | '3' | '4' | '5' | '>' | '>>' | '>>>' | '>>>>' | 'Ω';
type Rule = 'deadZone' | `delay:${number}` | 'silence' | 'commanderPick' | 'solo' | 'sick';
interface CTask { card: Card; token?: Token; owner?: string; done: boolean }
interface CPlayer { id: string; hand: Card[]; comm?: { card: Card; pos: 'top' | 'only' | 'bottom' }; commUsed: boolean }
interface CState {
  game: 'crew'; channel: string; host: string;
  phase: 'lobby' | 'assign' | 'trick' | 'ended';
  players: CPlayer[]; mission: number; unlocked: number;   // mission：1～40
  commander: number; sick?: string;
  tasks: CTask[]; picker: number;                          // 一般挑任務輪到誰；指派時是第幾張
  answers: Record<string, boolean>;                         // 指派／單人任務的「要／不要」
  trickNo: number; leader: number; turn: number;
  trick: { id: string; card: Card }[];
  transferUsed: boolean;
  outcome?: 'success' | 'fail'; reason?: string;
  seq: number; timerSeq: number; timers: { phase?: number };
}
```

### 11. Action 與指令、按鈕

- 指令：`/game crew new`、`start`、`cancel`、`level [n]`、`reset`、`help` (`addbot`／`removebot` 拒絕)
- 按鈕：`hand` (手牌)、`play:<seq>:<牌>`、`comm` (通訊選單)、`commCard:<seq>:<牌>`、`pick:<seq>:<任務序號>`、`assign:<seq>:<user>`、`answer:<seq>:yes|no`、`solo:<seq>:<user>`、`sick:<seq>:<user>`、`transfer`、`transferTo:<seq>:<任務序號>:<user>`、`resetConfirm`；共通 `join`、`leave`、`start`、`rematch`
- engine action 另有 `timeout { id }`；`new` 由 adapter 帶 `unlocked`

## Risks / Trade-offs

- [不能聊天無法強制] → 開局公告、指令說明和 wiki 都提醒；合作遊戲靠自律
- [出牌逾時自動出牌可能害整隊失敗] → 2 分鐘夠長，公告寫明是系統代出
- [3 人局剩下那張牌是任務牌時必敗] → 原版規則，說明提醒指揮官
- [通訊窗口很短：領出的人很快出牌，別人來不及通訊] → 說明提醒「想通訊的人在牌桌訊息出現時先按」，領出的人可以稍等
- [自編關卡難度可能不平均] → 關卡表集中在 `src/crewMissions.ts`，之後調整只改資料；測試只檢查格式 (40 關、任務數遞增趨勢、標記數 ≤ 任務數)
- [新增 GameEvent 和 `slack.ts` 改動與其他平行 change 衝突] → 改動集中在 `HostOptions`、`dispatchGame` 和 `send` 各一處
